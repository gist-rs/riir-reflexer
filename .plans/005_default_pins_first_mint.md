## The runbook (VERIFIED against `src/bin/reflexer.rs` at `60408d2`, 2026-10-01; the original draft's two corrections are folded in)

1. **Mint**: `reflexer sign --in <payload-file> --out <vessel-path> --key-id <u32> [--artifact-version <u64>=1] [--parent <blake3-hex>] (--key <64-hex-seed> | --key-file <path> | env REFLEXER_SIGN_KEY)` — `--key-file` accepts 64-hex text or 32 raw bytes. Fail-closed exit 2 on a missing key/`--in`/`--out`/`--key-id` or an over-cap payload (1 MiB public cap, enforced from metadata before load); exit 1 if the mint-side re-verification of the fresh bytes fails. Success prints one JSON line: `commitment` (the blake3 pin consumers record), `verifying_key` (the trust anchor to pin), `key_id`, `artifact_version`, `payload_len`, `vessel_len`. (Correction 1: payload is `--in`, not positional, and `--out`/`--key-id` are required — the drafted mint line would have exit-2'd.)
2. **Verify** (inspect without applying): `reflexer --vessel-print <vessel-path> --vessel-pubkey <verifying-key-hex>` — peeks the header, resolves the pin (compiled `default_pins()` first, the flag's wildcard only ADDS), strict-ed25519-verifies, prints JSON incl. `"signature": "verified" | "BAD" | "unverified: no pin for key-id N"` + the commitment. (Correction 2: `--vessel-print` takes the path itself and early-returns — it does not combine with `--vessel`. Full boot-verify instead: `reflexer --vessel <path> --vessel-pubkey <hex>` — verifies, applies the monotonic gate, serves stdio.)
3. **Pin**: file the owner call with the `verifying_key` hex from step 1 → land the `DEFAULT_PINS` row (compile-time pin table, keyed by the `key_id` used at mint) + set the consumers' operator pin (e.g. `RIIR_REFLEX_HEADS_PUBKEY` on the reflex side); re-run the vessel gates (`cargo test` in `crates/reflexer-vessel`).

- [ ] At the first public vessel mint: land the `DEFAULT_PINS` row + the consumers' operator pin per the runbook above (mint → verify → pin).
